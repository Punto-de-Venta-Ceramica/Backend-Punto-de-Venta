# BarroControl: base de datos con Hibernate

Backend con Java 21, Spring Boot, Jakarta Persistence/Hibernate y PostgreSQL.
Las entidades reproducen el script original: 19 entidades y cuatro tablas de
unión, para un total de 23 tablas. No hace falta ejecutar manualmente ese script.

## Base de datos y esquema

- **Base de datos en Render:** `barrocontrolbd`.
- **Esquema dentro de esa base:** `barrocontrol`, conservado del SQL original.
- Hibernate crea el esquema, las tablas, relaciones, índices y restricciones
  declaradas en las entidades al arrancar con `DDL_AUTO=update`.
- Después se ejecuta `src/main/resources/db/postgresql-complementos.sql`: crea
  las tres vistas, el índice único de correo normalizado y la clave foránea
  compuesta que comprueba que la caja de una venta es la del corte.
- `subtotal` y `diferencia` usan columnas `GENERATED ALWAYS AS ... STORED`
  y `@Generated`: PostgreSQL los calcula
  y Hibernate recupera sus valores al insertar o actualizar.
- Los detalles usan claves compuestas con `@EmbeddedId` y `@MapsId`. Las
  tablas de unión usan `@ManyToMany`, sin entidades adicionales.

El nombre `barrocontrol` en `CREATE SCHEMA` del script nunca fue el nombre
de la base de datos. Conectar a `barrocontrolbd` no requiere renombrar ese
esquema ni ejecutar `CREATE DATABASE`. Hibernate genera identidades de
PostgreSQL con `GenerationType.IDENTITY`; al crear tablas nuevas usa
`GENERATED BY DEFAULT`, compatible con la inserción de entidades del
script, cuyas identidades eran `GENERATED ALWAYS`.

## Datos que debes obtener de Render

En tu instancia de PostgreSQL, abre **Info / Connections**:

| Variable | Valor |
| --- | --- |
| `DB_HOST` | Host de **External Database URL** para conectar desde tu computadora |
| `DB_PORT` | Puerto, normalmente `5432` |
| `DB_NAME` | `barrocontrolbd`; comprueba el campo Database en Render |
| `DB_USERNAME` | Usuario de PostgreSQL |
| `DB_PASSWORD` | Contraseña de PostgreSQL |
| `DB_SSLMODE` | `require` para la conexión externa |

Si el backend se despliega en Render, puedes usar el host interno cuando
ambos servicios compartan región y red privada.

La URL de Render suele tener esta forma:

```text
postgresql://USUARIO:CONTRASEÑA@HOST:5432/barrocontrolbd
```

Para JDBC, configura usuario y contraseña por separado y usa:

```text
jdbc:postgresql://HOST:5432/barrocontrolbd?sslmode=require
```

Puedes poner esa URL completa en `DB_URL` en lugar de configurar
`DB_HOST`, `DB_PORT`, `DB_NAME` y `DB_SSLMODE`. En ambos casos debes
definir `DB_USERNAME` y `DB_PASSWORD`. Copia la contraseña del campo
Password de Render, sin codificación URL.

No necesitas compartir la contraseña en el chat ni guardarla en Git.
`.env.example` es una referencia: Spring Boot no carga automáticamente
archivos `.env`. Configura las variables en la terminal, tu IDE o el
entorno del servicio donde ejecutarás el backend.

## Arranque desde PowerShell

Desde esta carpeta del backend, usando Java 21:

```powershell
$env:DB_HOST = 'TU_HOST_EXTERNO_DE_RENDER'
$env:DB_PORT = '5432'
$env:DB_NAME = 'barrocontrolbd'
$env:DB_USERNAME = 'TU_USUARIO'
$taskCredential = Get-Credential -UserName $env:DB_USERNAME -Message 'Contraseña de PostgreSQL en Render'
$env:DB_PASSWORD = $taskCredential.GetNetworkCredential().Password
$env:DB_SSLMODE = 'require'
$env:DDL_AUTO = 'update'
.\mvnw.cmd spring-boot:run
```

Render debe mostrar la base como **Available**, y sus reglas de acceso
externo deben permitir la IP pública desde la que te conectas. El usuario
debe tener permiso para crear el esquema y sus objetos.

Cuando aparezca `Started PuntoventaapiApplication`, comprueba en pgAdmin
o psql, conectado a `barrocontrolbd`:

```sql
SELECT current_database();
SELECT table_name
FROM information_schema.tables
WHERE table_schema = 'barrocontrol' AND table_type = 'BASE TABLE'
ORDER BY table_name;
SELECT * FROM barrocontrol.vw_venta;
SELECT * FROM barrocontrol.vw_corte_caja;
SELECT * FROM barrocontrol.vw_pedido;
```

Si aún no hay datos, las vistas estarán vacías. Para empezar a registrar
operaciones faltan los servicios y endpoints, el alta inicial de negocio,
rol, usuario, sucursal y caja, y la lógica transaccional para existencias,
ventas, pedidos y cortes. El campo `password_hash` requiere un hash de
contraseña generado por la futura capa de autenticación. No se crea un
usuario administrador con contraseña predeterminada.

## Pruebas

Las pruebas de integración necesitan una base PostgreSQL exclusiva para
pruebas. No uses la base del negocio: generan el esquema y ejecutan
inserciones dentro de transacciones que se revierten.

```powershell
$env:TEST_DB_URL = 'jdbc:postgresql://localhost:5432/barrocontrol_test'
$env:TEST_DB_USERNAME = 'TU_USUARIO_DE_PRUEBAS'
$env:TEST_DB_PASSWORD = 'TU_PASSWORD_DE_PRUEBAS'
.\mvnw.cmd test
```

Sin `TEST_DB_URL`, las pruebas se omiten explícitamente. Cubren creación
de tablas y vistas, relaciones, claves compuestas, columnas generadas,
correo único, inventario no negativo, caja del corte y notificaciones.

## Cambios posteriores

`update` sirve para crear y evolucionar el esquema inicial; no sustituye
migraciones versionadas ni adapta de forma fiable todas las restricciones
de tablas ya existentes. No renombres columnas esperando que Hibernate
conserve sus datos automáticamente. En producción conviene pasar a
migraciones con Flyway/Liquibase y `DDL_AUTO=validate`.
El complemento SQL sigue necesitando permisos para crear o reemplazar
vistas; ajusta también ese mecanismo al introducir las migraciones.
Evita `create` y `create-drop` sobre la base del negocio: eliminan datos.
